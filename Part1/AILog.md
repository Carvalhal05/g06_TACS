## Problems found and how we detected them

| Session | What was wrong | How we detected it | How we fixed it |
|---|---|---|---|
| 15 | The first version of the Laptop instance proposed by the LLM had a requires constraint between two members of the same Or group (stylus requires touchscreen). In our report, a cross-tree constraint links features in different branches of the tree. | Checking the proposed instance against our definition of `CrossTreeConstraint`. | We removed the constraint and recomputed the clause and solution counts by brute force. |
| 15 | Example.md did not match the B-UML object model: the request was "soGPS" instead of "onlyGPS", the variable was "heartRate" instead of "heartrate", and the FeatureModel row had no `constraints` or `requests` links. | Comparing Example.md with the B-UML file exported from BESSER. | We updated Example.md to use the object names and links of the model. |
| 15 | Not an LLM error, found in the same session: the BESSER-generated `.py` writes the six parent/children links of the problem object model as self-links (for example `display_obj.children = display_obj`). | Comparing the `.py` with the BESSER project (JSON) and the object diagram image. | We documented the issue in Example.md and kept the JSON project as the reference. |
| 16 | Not an LLM error: our first extension of the SmartWatch had heart rate twice, as a sensor in the Or group and as a data item of the digital display. A feature has one parent and a unique id. | The LLM checked the proposal against our OCL rules (`UniqueFeatureIds`, one parent per feature). | We kept heart rate only as a sensor. |
| 16 | The self-links of session 15 were still in the `.py`. | A script that loads the `.py` and checks our OCL rules reported cycles (`NoCycles`) and group members that are not children of the group's parent (`MembersAreChildren`). | The links were rewritten when the model was extended; the same script now reports no violations. |
